# Визуальный редактор сценариев — Руководство пользователя

Визуальный редактор сценариев — это внутриигровой GUI, предназначенный для сборки сценариев NPC в моде **Envoys** без ручного написания Lua. Он превращает граф узлов в генерируемый скрипт `main.lua`, управляющий поведением NPC, и умеет выполнять обратное преобразование этого скрипта в редактируемый граф.

Это руководство описывает процесс создания сценария: как устроены цепочки, как открыть редактор, что означают состояния событий и как работает поток «Обработать сценарий» при сохранении.

---

## Цепочки графа

У каждого события есть **цепочка** узлов. Цепочка всегда начинается со специального узла `start` — точки входа для этого события.

- Каждый узел имеет числовой **ID**.
- Каждый узел имеет поле **Next** (подписано как «Далее») — ID следующего узла в цепочке.
- Пустое поле **Next** означает, что узел является **концом цепочки**.

Когда событие срабатывает, выполнение идёт по цепочке от `start`, следуя указателю Next каждого узла, пока не достигнет узла без Next — или пока узел ветвления не перенаправит выполнение на другой головной узел.

Узлы редактируются на экране **«Визуальный сценарий» (Visual Script)**, который открывается из настроек NPC.

---

## Открытие редактора

Когда вы открываете экран «Визуальный сценарий» (Visual Script):

1. Клиент запрашивает у сервера файл `main.lua` этого NPC.
2. Скрипт **декомпилируется** в граф.
3. На экране отображаются четыре события, которые может содержать скрипт.

Если файл содержит код, созданный не редактором, затронутое событие защищается Safe Guard (см. [INTERNALS_AND_SAFETY.md](INTERNALS_AND_SAFETY.md)), а не перезаписывается.

## Состояния событий

В каждой строке события отображается индикатор состояния:

| Состояние | Индикатор | Значение |
| --- | --- | --- |
| Сохранено / синхронизировано | 🟢 зелёный | Граф на экране совпадает с сохранённым скриптом. |
| Есть правки | 🟡 жёлтый | Граф был изменён и отличается от сохранённого скрипта. |
| Заблокировано (внешний Lua) | ⚪️ серый | В этом событии обнаружен Lua-код, созданный вне GUI. Визуальное редактирование отключено, кнопка **Настроить** для этого события недоступна. |

Кнопка **Настроить** отключена только для ⚪️ серых (заблокированных) событий.

## Кнопка «Обработать сценарий»

Кнопка **Обработать сценарий** доступна только при наличии изменений — то есть когда хотя бы одно событие 🟡 жёлтое.

При нажатии редактор:

1. Компилирует граф в Lua.
2. Выполняет предварительную проверку сгенерированного Lua на синтаксические ошибки.
3. Показывает модальное окно с тремя режимами сохранения.

### Режимы сохранения

- **Отправить и перезапустить** — записывает `main.lua` NPC на сервер и перезапускает Lua-движок NPC, чтобы новое поведение вступило в силу немедленно.
- **Только отправить** — записывает `main.lua` на сервер без перезапуска движка. Новый скрипт вступит в силу при следующем запуске движка.
- **Только локально** — сохраняет файл на клиенте в `.minecraft/envoys/local/`, не затрагивая сервер.

После успешной отправки или локального сохранения редактор удаляет резервную копию `.temp`, а затронутые события становятся 🟢 зелёными.

## Настройка события

Помимо самого графа, у каждого события есть экран настроек, где можно:

- **Включить / отключить** событие.
- Задать **аргумент** события — например, **интервал обновления в тиках** или **радиус действия в блоках**, в зависимости от события.

Отключённое событие сохраняет свою цепочку нетронутой, но каждая исполняемая строка генерируемого Lua **выводится закомментированной**, поэтому событие никогда не выполняется, оставаясь полностью редактируемым.
