# Квесты

Квесты дают игрокам долгосрочные цели с отслеживаемым прогрессом. Их можно создавать двумя способами:

- через меню квестов NPC прямо в игре (кнопка **«Квесты»** на экране настроек NPC), либо
- полностью из Lua-скрипта, используя API `envoys.quest.*` (см.
  [Quest API](lua/QUEST_API.md)).

У каждого квеста есть два идентификатора:

- **`local_id`** — короткий, читаемый человеком идентификатор, уникальный в пределах владеющего NPC
  (например `intro` или `cake_truth`);
- глобальный **`quest_uuid`** — стабильный уникальный id в пределах всего мира, используемый для
  ссылки на квест из любого скрипта или команды.

Скрипты и команды принимают любую из форм; при разрешении сначала проверяется текущий NPC, а затем
происходит откат к глобальному индексу квестов, причём сравнение UUID игнорирует дефисы и регистр букв.

Заголовки, id и логика наград квестов — это **пользовательские данные**: они не локализуются, и
движок никогда не выдаёт награды сам по себе. Что даёт квест при завершении, решает скрипт.

## Типы квестов

Существует три типа квестов. Они различаются только способом измерения прогресса.

### KILL

Уничтожить заданное число мобов определённого типа (идентифицируемого по entity id, например
`minecraft:zombie`). Прогресс считает зачтённые игроку убийства до достижения требуемого количества.

### ITEM

Собрать заданное число определённого предмета в инвентаре игрока. Прогресс **динамический**: он
вычисляется по предметам, которые игрок держит прямо сейчас, поэтому прогресс растёт и падает по мере
получения или потери предметов. Просто от того, что предметы лежат в инвентаре, ничего не расходуется —
см. замечание в [Quest API](lua/QUEST_API.md) о расходовании предметов при завершении.

### BOOLEAN

Чек-лист скриптовых **этапов** для продвижения по сюжету/сценарию. Прогресс считает число уникальных
этапов, которые скрипт отметил выполненными. Используйте это для многоэтапных квестовых линий, где
скрипт сам решает, когда каждый этап завершён.

## Интерфейс для игрока

- **Стена квестов (журнал):** нажмите **J** (по умолчанию, переназначается в Настройках управления),
  чтобы открыть экран «Стена квестов», который перечисляет квесты игрока и их прогресс.
- **Закрепление:** щёлкните квест на «Стене квестов», чтобы **закрепить** его для отслеживания.
- **HUD-оверлей:** закреплённый квест отображается в **правом верхнем углу** экрана с живым
  значением прогресса, которое обновляется по мере продвижения квеста.
- **`visible_in_gui`:** флаг отдельного квеста. Когда он отключён, квест скрыт из HUD-оверлея,
  но остаётся видимым в журнале «Стена квестов».

## Связь со скриптами

Описанная выше концепция рассказывает, *что такое квест* и *как его видит игрок*. Скриптовый
контракт — значения статуса, таблицы прогресса и функции запуска, продвижения и завершения квеста —
живёт в [Quest API](lua/QUEST_API.md), а квестовые узлы визуального редактора описаны в
[Справочнике действий](gui/ACTIONS.md).
